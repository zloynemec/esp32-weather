# Telegram Bot

Отдельное приложение-представление для погодной станции. Бот получает команды из
одного настроенного Telegram-чата и читает данные через Server API.

Server API хранит события значительных изменений в SQLite. Бот проверяет очередь
каждые 2 секунды, отправляет одно объединенное сообщение для температуры и влажности
и подтверждает событие только после успешного ответа Telegram. Поэтому временная
ошибка доставки не теряет уведомление.

## Команды

- `/weather` — последнее измерение датчика по умолчанию (или единственного датчика);
- `/weather <device_id>` — последнее измерение конкретного датчика;
- `/devices` — список зарегистрированных датчиков;
- `/chart` — общий график температуры и влажности за сутки;
- `/chart hour|day|week|month` — период час, сутки, неделя или 30 дней;
- `/chart <period> <device_id>` — график конкретного датчика;
- `/help` — справка.

Server API агрегирует данные максимум до 168 точек. Бот локально строит PNG
1200×720: температура показана красной линией и левой шкалой, влажность — синей
линией и правой шкалой.

## Настройка

Добавьте бота в нужную группу, затем задайте в корневом `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=token-from-botfather
TELEGRAM_CHAT_ID=-1001234567890
WEATHER_API_URL=http://127.0.0.1:3000
TELEGRAM_DEFAULT_DEVICE_ID=esp32-wokwi-01
TELEGRAM_TIME_ZONE=Europe/Simferopol
```

Токен нельзя коммитить. ID группы можно узнать, отправив сообщение в группу до
запуска приложения и открыв
`https://api.telegram.org/bot<TOKEN>/getUpdates`: значение находится в
`result[].message.chat.id`. Если Bot API возвращает пустой `result`, остановите бот,
отправьте адресованную ему команду `/start@username_бота` в группе и повторите запрос.

Server API и бот запускаются в отдельных терминалах из корня репозитория:

```bash
npm run dev:server
npm run dev:bot
```

При старте бот проверяет токен, регистрирует меню команд и начинает long polling.
Сообщения из чатов, отличных от `TELEGRAM_CHAT_ID`, игнорируются.
